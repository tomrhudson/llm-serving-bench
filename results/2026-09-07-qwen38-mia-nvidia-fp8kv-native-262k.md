# Qwen3.8 Flash Next: updated MiaAI recipe with NVIDIA NVFP4 and FP8 KV

Date: 2026-09-07

Status: **PASS — 601/601 requests; 13/13 standard-suite quality checks.**

Use concurrency 8 for this workload. Sustained throughput was essentially unchanged from August 31, while 240K first-token latency improved by 15.4%. Short decode at c8 and warm-prefix latency were slower. This was a shared-service run with two small overlapping requests, detailed below.

Serving recipe: [MiaAI-Lab dual-Spark recipe](https://github.com/MiaAI-Lab/Qwen3.8-Flash-Next-Dual-DGX-Sparks/tree/c2325b22602b51a5faf55fc2bebccc34f3f80b9f), commit `c2325b22602b51a5faf55fc2bebccc34f3f80b9f`.

### Checkpoint metadata compatibility

NVIDIA's later revision `fc694b54fb0174e0913e6adf86691ef85a4ead47` renamed the MTP experts' quantization metadata from `FP8_BLOCK_SCALES` to `FP8_PB_WO`. This recipe rejects the latter in preflight. The deployment pins `fab0aec` using revision arguments and the isolated offline cache reference. Hugging Face LFS metadata confirmed that all 11 safetensors files (132,680,249,378 bytes) are identical between the two revisions. No recipe source or checkpoint weights were modified for compatibility.

Runtime overlays are those generated by the pinned recipe: FP8 KV/QSA support, PLE dtype and loader handling, MTP index aliases, and the ModelOpt FP8 block-scaled MoE dispatch.

## Comparison with August 31

|---|---:|---:|---:|
| c1 output tok/s | 48.93 | 47.34 | -3.3% |

| c8 soak output tok/s | 197.71 | 197.42 | -0.1% |
| 240K TTFT seconds | 117.30 | 99.22 | -15.4% |

These are separate-day serving-system baselines. Checkpoint, KV precision, context limit, and runtime overlays changed together; differences cannot be attributed to FP8 KV alone. The September 3 baseline additionally used a 2200 MHz graphics-clock cap.

Warm shared-prefix TTFT p95 increased from 4.04s to 5.86s, even though unique and cold shared-prefix requests became faster. The new configuration is not a uniform latency improvement.

The old recipe advertised a 1,000,000-token limit with a YaRN flag. Upstream subsequently documented that its old top-level override never reached `text_config`, so effective YaRN scaling was not established in those historical runs. Their measured 240K results remain useful; they never validated quality at 1M. The updated run explicitly uses native 262K with YaRN off.

## Validation and method limits

- Both rank containers remained running with no OOM flag or restarts; direct health/generation and authenticated routing were verified after the benchmark.
- The backend drained to zero running/waiting requests. Server abort and error counters stayed at zero. Routed postflight verified the expected backend and zero retries/fallbacks.
- The server counted 603 completions during the 601-request benchmark. Router access logs confirmed two overlapping routed requests; aggregate counter deltas showed 126 additional prompt tokens and 82 additional output tokens. These are excluded from the benchmark's reported request and throughput totals, but their resource contention cannot be removed from measured latency. Treat this as a shared-service baseline, not a fully isolated comparison.
- The unchanged harness could not flush cache through its `/flush_cache` endpoint. Scenario-specific prompts and the deliberate shared-prefix pair were retained; the cold labels do not establish a fully reset server cache.
- The log scan found Transformers video-processor docstring messages labeled `ERROR`, but no traceback, CUDA OOM, or NCCL failure. The text-only suite does not validate image/video serving.
- Minimum sampled available RAM on rank 0 was 3.02 GiB, with swap already occupied after startup. Preserve the measured memory settings; this run does not justify raising GPU memory utilization or adding another GPU workload.
- Clients configured for the previous advertised 1M limit need to match this deployment's 262,144-token server limit.
- Greedy temperature 0 is specified by the standard suite. Streaming TTFT starts at the first content or reasoning token; chunk intervals approximate token latency.
- Raw requests, generated reasoning, private network endpoints, SSH targets, and host identifiers are excluded from this report. Raw JSON and operational evidence remain private.
